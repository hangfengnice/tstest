# 每日自评模板

复制到当天 NOTES.md 的自评节，由学习者本人填写；已有复盘保留，只补缺失信息。
每天用三句话完成，复杂问题再展开；证据只存一份，项目已有记录时引用并补充本人完成部分，不要求两边重复写长复盘。

1. 今天最卡的是：____；我选择这个类型设计的原因是：____。
2. 我获得了 ____ 次提示（不记得写“未记录”），帮助来自 ____，提示内容是 ____。
3. 下一次我准备在 ____ 场景验证 ____；或引用已有的后续独立项目证据 ____（日期、本人修改和验证范围）。

提示包括 AI、他人指导和参考答案；主动查文档也记录，但不直接等同于没有掌握。

## 验收记录

- 当天代码：`pnpm check:day XX`，结果 ____。
- 解释：为什么选这个设计？一个错误用法为什么应当被拒绝？____。
- 隔天重做/独立项目迁移：日期 ____；选择小实验或真实项目；本人完成 ____；实际验证 ____；证据链接 ____；仍需要的提示 ____。
- 部分学习时：基础已学 ____；复杂边界待补 ____；命令失败中属于待补部分的错误 ____。项目证据不替代原题整题验收。

小实验优先写进独立 transfer 文件，保留原题和原测试；使用变化后的场景和针对性验收用例。若选择在原文件重做，先保存原实现，验证后恢复，不覆盖未保存的代码。原题未完成时 check:day 仍可能失败，分别记录小实验与整题结果。
已有同主题的后续独立项目修改和验证，可直接替代这次迁移/重做；当天照抄、仅阅读和 AI 代写后的讲解不算独立证据。
空白记录表示尚未验证，不自动推断为掌握或不掌握。

## 从 Day 1 重学时的追加格式

保留原 NOTES，在末尾追加，不替换旧结论：

```markdown
## 重学 YYYY-MM-DD

- 本次完成范围：
- 当天验收命令与实际结果：
- 能独立解释的概念及反例：
- 获得的提示、来源、次数：
- 隔天重做或独立项目迁移的场景、日期、实际结果与证据链接（完成后填写）：
- 尚未完成的题目范围/待补项：
- 自评（本人填写）：
```

将三项结果同步到 [本轮重学记录](./RELEARNING-PROGRESS.md)。运行参考答案验证、整理文档或提交文件，不计为本人完成练习。
